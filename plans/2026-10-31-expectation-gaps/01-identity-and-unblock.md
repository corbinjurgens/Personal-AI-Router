# Execution plan: Phase 01: model identity and unblocking the owner's machines

## Goal
Overall goal of the batch (`README.md` in this folder, sections 4 and 5): PAIR
manages the owner's three-machine cluster as role → profile → engine, shows every
model by its true identity, estimates and validates profiles, and routes by
speed and context. This phase is the first step and is independent of the
others. When it is done, on MSI and Joes **as they are today** (hand-written
llama.cpp presets, user-installed builds such as b11219), PAIR can inspect and
copy-export every llama.cpp model on the engine, shows each model's true
identity (repository, quantization, content id, architecture, size, configured
context) as tags in the desktop and the TUI instead of only the preset section
name, can express the owner's MoE placement (`n-cpu-moe`, `cpu-moe`, `repack`,
split, device, extra per-model flags) and llama.cpp native fit (`fit`,
`fit-target`, `fit-ctx`) in typed loads, records `build_info` for any build that
answers `/props`, enumerates devices on builds whose ggml device layout is
verified, and lists the flags the detected `llama-server` build supports. The owner wants this because every
later phase (profiles, roles, estimate, routing) keys on a model identity that
PAIR does not publish today, and because MSI and Joes cannot currently be
inspected, exported or measured at all (README section 2, causes 2 and 3).

## Change scope
Intent: PAIR reads hand-written presets only as far as it needs to find files, publishes a computed model identity, types the owner's placement and native-fit options, and stops refusing builds other than b11146 everywhere except device enumeration of an unverified ggml layout.
Scope: Bounded improvement — improve the existing owners in place: the artifact resolver (`modelcopy_export.go`), gguffacts, the engine-manager inventory (`ModelsResult`) and its relays, the typed load vocabulary (`modelconfig.RequestedLoad` and its compiler), the device and buffer build gates, and the desktop and TUI labels; leave profiles, roles, node-policy `Profile`, routing order, strict admission and the desktop information architecture unchanged.
Basis: README section 5 row 01 and owner decision D6 (README section 6); the repository rules in `.cursor/rules/services-change-propagation.mdc`, `service-contracts.mdc`, `type-discipline.mdc`, `no-legacy-fallbacks.mdc`, `renderer-stores.mdc`, `engines-vs-backends-naming.mdc`; the fork rule "pre-release fork: no compatibility work".
Compatibility: strict serving-envelope parsing (`parseLlamaServingPreset`) keeps its behaviour for operator-declared serving presets; strict admission keeps using `ModelDigests` and serving envelopes only; the install manifest still installs pinned b11146 artifacts. Wire formats change in place with no version bump, capability marker or migration.
Non-goals: profile keys, multiple configurations per model (phase 02a), preset import (phase 02b); role names (phase 03); Models/Profiles tabs, node settings page, engine toggles (phase 04); estimate visibility and the diagnostic run (phase 05); routing by speed or context, the smart-routing plan beyond its Task 1 identity (phase 06); Strata; Ollama and LM Studio identity.

## Decisions made while writing this plan
- **contentId has no strict-admission meaning.** It travels in a new `modelContentIds` map beside `modelDigests`, never in `ModelDigests`; strict admission, readiness and hybrid eligibility keep using serving digests only. It is display and measurement identity. Rationale: writing it into `ModelDigests` would grant strict meaning to an unverified LFS name (L2 Q5).
- **contentId covers the model-role shards only** (not draft or companion files), so the same GGUF compares equal across nodes whatever draft or mmproj a preset adds. It therefore differs from a serving envelope's `contentDigest` when that envelope has a draft.
- **Lenient reader key set:** artifact lookup reads only `models-preset`, `model`, `model-draft`, `ctx-size`, `parallel` from CLI, env, `[*]` and the section (same precedence as today: env, `[*]`, section, CLI); every other key is ignored; structural problems are recorded on the affected section only.
- **Resolver refusals become `*ServingFieldError`** (fixed reasons, never paths) so inspection, typed preview and conversion show the real reason; other errors keep today's generic messages.
- **Wire shape:** shared type `engines.ModelIdentity` in `services/shared/engines/model_identity.go`; `ModelsResult.modelIdentities` and `DirectoryNode.modelIdentities` are `engine → model → identity`; identities exist for llama.cpp engines only (Ollama and LM Studio entries are absent; their inventory digests are not GGUF content hashes).
- **Identity work is off the sweep path:** a refresher resolves identities after full-inventory sweeps and a single background hasher hashes files one at a time into `<appdir>/model-content-hashes.json`; the sweep only reads the cached snapshot.
- **Quant label priority:** HF tag from the model id, then the model file name, then `general.file_type`. Unsloth `UD-` quants report a base `file_type`, so the file name ranks above GGUF metadata.
- **`ModelItem.quantization` and `digest` are removed** (desktop shared and ui types) and replaced by `identity?: ModelIdentity`; their only writers wrote `''`.
- **Labels:** the repository tag shows the full `owner/name` (owner's expectation 2 wording); the primary label is the identity-derived name with the quant kept, e.g. `LFM2.5 24B A2B (UD-Q4_K_XL)`; the raw served id stays in `title` and as a muted "Served as …" line when it differs; a "Context N" tag shows the configured per-slot context.
- **Typed field shapes:** `nCpuMoe` int32 ≥ 0; `cpuMoe` bool (true emits `cpu-moe`, false emits nothing) and exclusive with `nCpuMoe`; `repack` bool; `splitMode` enum `none|layer|row`; `tensorSplit` and `device` validated strings; `mainGpu` int32; `device` is refused together with GPU mode `auto`; `fit` enum `off|auto` (unset means `off`); `fitTarget` a string of one MiB value or one per device (`"512"`, `"1024,512"`), because llama.cpp broadcasts a single value and also takes a per-device list; `fitCtx` int32 ≥ 0. `splitMode`, `tensorSplit`, `mainGpu`, `device`, `fitTarget` are not portable (hardware-specific); `nCpuMoe`, `cpuMoe`, `repack`, `fit`, `fitCtx`, `extraFlags` are portable.
- **Native fit has no finite allocation.** A load with `fit: "auto"` hands placement to llama-server, so PAIR claims nothing about its memory: it gets no configuration key (inspection reason `native-fit`), no estimate verdict (estimate status `native-fit`, shown as "Native fit, unpriced"), no buffer capture and no stated or measured memory record. It still compiles, serves, routes, imports and deploys like any typed load (owner: untested profiles may still be assigned). `fit: "auto"` is refused together with GPU mode `auto` (reviewed Auto placement) and with `device`; `fitTarget` and `fitCtx` are refused unless `fit` is `auto`. The native value written for `auto` is `on` (llama.cpp `--fit on|off`); the configured per-slot context stays the declared bound, although native fit may lower the launched context toward `fitCtx` (not verifiable here; read `/props` on Joes during acceptance).
- **Extra flags:** `extraFlags: [{flag, value?}]`, at most 32, flag `^--?[A-Za-z0-9][A-Za-z0-9_.-]{0,63}$`, value at most 1024 bytes with no control characters and none of `# ; $ % { }` or backtick (characters the preset format cannot carry). `| & < >` are allowed because the value is written to an INI file, never to a shell or launch text, and override-tensor regexes use `|`. Keys PAIR types or owns are refused with a named reason. External-preset conversion maps every non-typed, non-PAIR-owned key to an extra flag.
- **Estimate honesty:** when any new placement field or extra flag is set, the estimate adds the unknown `expert, split, device and extra-flag placement unpriced`.
- **Build identity storage:** `engineState.buildInfo` (set after readiness, cleared on stop), exposed in `EngineStatus.buildInfo` and `InspectResult.nativeBuild`; `ServingReadback` is unchanged (build belongs to the engine run, not the serving envelope). An empty build yields no configuration key (reason `build-unknown`).
- **Device root:** the install directory when the binary is a managed install, otherwise the directory of the detected binary. The ggml commit is recorded and selects the props layout from an allow-list `modelGGMLPropsLayouts` (one entry per verified build: build label, full ggml commit, struct size, `ID` offset; b11146 / `7fe450e19305b828c199d602c23a8337aaa1f03b` / 56 / 40 now). An unlisted commit ends device enumeration with `devices unavailable: unverified ggml layout`; nothing else gates on the list. Adding a build means reading its `ggml-backend.h` and adding an entry whose layout equals the Go struct; a build whose layout differs needs a new struct and is out of this phase.
- **Help flags** are cached per binary (path, size, mtime), exposed in `InspectResult.nativeFlags`, not in `engine:status` (polled and broadcast); extra flags are checked against the list only when it is known for the current binary. Task 11 is last and **may be deferred**: the executor defers it only when its Verify cannot pass in this session (see If stuck); Tasks 1-10 do not depend on it. A deferred Task 11 gets ` — dropped` on its heading per the lifecycle and a `project-note deferred` entry.

**Do:**
1. In `serving_llamacpp.go`, next to `parseLlamaServingPreset` (leave that function unchanged), add the lenient reader:
   ```go
   // llamaArtifactKeys are the only options artifact lookup reads.
   var llamaArtifactKeys = map[string]bool{"models-preset": true, "model": true, "model-draft": true, "ctx-size": true, "parallel": true}

   type llamaArtifactSection struct {
   	options map[string]string // canonical artifact key -> value
   	err     error             // *ServingFieldError when this section cannot be used
   }

   // readLlamaArtifactPreset reads a hand-written preset only to locate
   // artifacts. Unknown and envelope-affecting keys are ignored; structural
   // problems are recorded on the affected section. The serving-envelope
   // compiler keeps parseLlamaServingPreset.
   func readLlamaArtifactPreset(data []byte) (map[string]llamaArtifactSection, error)
   ```
   Rules: scan with the same `bufio.Scanner` bound as `parseLlamaServingPreset` (`servingSmallFileLimit`); a scan failure is the only whole-file error besides a `key=value` line before any section (`servingError("Preset requires explicit sections.")`). Skip blank lines, `#`/`;` comment lines and the `version` key. A `[name]` header seen twice sets that section's `err` to `&ServingFieldError{Field: "preset", ModelID: name, Reason: "Duplicate preset section."}`; a non-`*` name failing `validateLlamaModelID` is recorded with `Reason: "Section name is not an exact model ID."`. Resolve each key with `llamaPresetOptionKey`; ignore keys not in `llamaArtifactKeys` (including unresolvable names, `load-on-startup` and every `unsupported` key).
