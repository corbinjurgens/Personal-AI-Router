# L2 — Model identity for llama.cpp: why the owner sees preset names, and what true identity (repo, file, quant) PAIR can know
Baseline: integration/join33 4eccd05d. Investigated: 2026-10-31.

## Verdict
For llama.cpp, PAIR's model identity is only the native `/models` `id` string. The `llamacpp.json` `list_models` spec reads `data[].id` and nothing else, with no `digest` field. The only per-model wire shape is a bare string in `ModelsResult.ByEngine`. So in external-router preset mode (MSI, Joes), the name is the INI section name. In llama.cpp-managed HF-cache mode the name happens to be `owner/repo:QUANT`, but the desktop formatter then removes both the owner and the quant. PAIR does parse the preset, despite the sweep note's "without reading it". It parses it only on demand, for artifact resolution (inspection, typed conversion, peer-copy export), with the strict serving-envelope parser. That parser refuses MSI's keys, and that refusal is the export bug. Nothing PAIR resolves (file name, HF repo or revision, LFS sha256, ctx-size, GGUF `general.*`) reaches display, inventory or identity. A cross-node content identity exists only in the operator-declared serving-envelope mode (`servingContentDigest`, path-free and node-independent), which nobody uses. Unconfigured, typed and HF-cache llama.cpp runs publish no model digest. That digest gap is also why routing measurements are suppressed for llama.cpp.

## Findings

### Q1. llama.cpp configuration modes and how each names its models
1. **HF-cache (manifest default).** The launch sets `LLAMA_CACHE={models_dir}`. `pull_model` POSTs `{"model":"<repo:quant>"}`. The advertised ID is native `/models` `id`, for example `empero-ai/Qwen3.8-2B-Distill-GGUF:Q8_0`. PAIR can resolve the repo, tag, snapshot commit, selected file names, sizes and LFS sha256 on demand (`resolveBoundedLlamaCacheArtifacts`), but publishes none of it. ModelDigests stays empty because the manifest has no `digest` spec.
2. **Unconfigured external router (MSI, Joes).** The launch text carries `--models-preset <ini>`, and there is no `serving` and no `ModelLoads`. ID = INI section name. PAIR knows nothing persistently; it parses the INI only when inspect, typed conversion or export asks (C3). No digest.
3. **Serving envelope / finite llama router** (`LAUNCH_TEXT.md` "Finite llama router launch"; `serving_llamacpp.go` `compileLlamaServingSectionsExpected`; `shared/engines/serving.go` `ServingConfig`). The operator declares, per `modelId` (still the section name), the artifacts with `sha256`, provenance (`hf-lfs-sha256|one-time-sha256|supplied-sha256|…`), local binding (path, size, mtime, sample) and memory. PAIR publishes `ServingEnvelope` (contentDigest, per-slot and total context, slots, placement) in `engine:model-identity`. This is the only mode with a real identity, but it still has no repo or quant label.
4. **Typed / manager-owned typed presets** (model-setup Task 6: `f7cb8430`, `38c2cd39`; `modelsettings_load.go` `compileTypedLlama*`, `typedLlamaPreset`, `validateTypedLlamaConversion`). This mode converts the current external preset into a PAIR-generated preset per `ModelLoad{ModelID,…}`. `ResolvedLoad` carries `ArtifactBinding` (path, size, mtime, sampleSha256) and `PerSlotContext`. The ID stays the section name. There is no content digest unless a serving declaration also exists (C9).

In every mode, `Executor.ModelsResult` gets IDs only through `modelsSweep` → `extractReadyStringsResult` on the native list.

### Q2. Preset parsing in unconfigured mode
It exists (C3, C4), so the sweep note's "without reading it" is outdated. It does not feed inventory or identity, though. `parseLlamaServingPreset` returns `section → {key: value}` for the known keys. It refuses the whole file on any `unsupported` key except `model`, `model-draft` and `load-on-startup`, on any unknown key, on inline comments and on substitutions. Section names must also pass `validateLlamaModelID`. `llamaConsumedPaths` then requires a local `model=` path. The section name is therefore the only identity PAIR uses. The `model` path, which on HF-cache-backed files includes `models--owner--repo/snapshots/<commit>/<file>.gguf`, is used only to bind artifacts. No reverse path→repo mapping exists: only the forward `llamaRepoDir` produces `models--` (positive control).

### Q3. gguffacts
`Shard` keeps Architecture, Alignment, a numeric allowlist (`context_length`, `block_count`, `expert_count`, `expert_used_count`, rope/ssm dims, sampler defaults), vocabulary and merge counts, template digests, and tensors (name, ggml type, dims, bytes, layer). It does not keep `general.name`, `basename`, `size_label`, `file_type`, `quantized_by` or `repo_url` (C12). Users: inspection Facts (`modelsettings_artifacts.go`) and the memory estimate (`modelsettings_estimate.go`, via gguf-parser-go adaptation), plus calibration tooling. It is never used for display identity. A quant label could be derived from the tensor-type histogram today, but `general.file_type` would need one allowlist line. Inspection fails for MSI anyway because it uses the same resolver (C5).

### Q4. HF cache naming
Yes, this is the only path where the name carries true identity today. `splitLlamaModel` mirrors llama.cpp `common_download_split_repo_tag`. `llamaCanonicalModelID` uppercases the tag after the last colon, the same way preset.cpp does. `NormalizeModelName` is a no-op for llama.cpp (`model_naming: "exact"`). The catalog (`catalog.go`, "repo:quantization") produces these IDs for pulls. Nothing marks a name as HF-derived versus an alias, and the desktop then removes the quant (C16).

### Q5. Digests and cross-node sameness
`modelIdentity` → `engineModelIdentity{EngineRunID, LaunchDigest, ModelDigests, Serving}`. ModelDigests come either from inventory `extractDigests`, which only Ollama supplies, or from serving envelopes. Consumers are strict admission and residency (`nvpair-proxy/readiness_contract.go`, `residency.go`), memory evidence, performance identity (C10) and the proxy `/v1/models` conflict check.

To say "MSI and Joes serve the same GGUF", the right key is `servingContentDigest`'s formula: ordered (role, size, full sha256), path-free and name-free. The sha256 can come from:
- (a) the HF LFS blob name, free in HF-cache layouts, provenance `hf-lfs-sha256`;
- (b) the linked-model "checked hashing" (`modelfiles.go` `hashCache`, Tasks 2h and 2o), which already computes full sha256 for export but only in memory and only during copy;
- (c) an operator declaration.

The linked-model tasks give the means (bound checked reads, exact HF source bindings with blob sha256) but publish no persistent content identity. A GGUF header hash or repo+file name alone is weaker. Repo+file+revision is a good display key and a cheap pre-match, but only a sha256 establishes sameness. Writing such a digest into `ModelDigests` would grant strict-admission meaning. That is why the routing plan says "never manufacture a digest". A separate non-strict `contentId` is the safe vehicle.

### Q6. Display
Model Manager rows use `formatModelDisplayName(name, backend.type)`. Role tags use `roleLabel` with the raw ID. Model settings preview shows the opaque artifact identity, size, assurance and a facts status. Wire per-model data is `ModelItem{name,size,downloaded,downloadState}`, populated from `ModelsResult` strings. Without new wire fields the desktop can only (i) stop stripping `:QUANT` and the owner for `repo:quant` IDs and (ii) show architecture and context from an explicit `InspectModel` call, which fails on MSI. Repo, file, quant, revision and content identity for preset-mode models need new per-model metadata in `ModelsResult` or a sibling notification.

### Q7. Peer copy in preset mode
`Manager.executeCopy` → `llamaExportFiles*` → `resolveLlamaArtifactsSelection`. With a preset present, `llamaLaunchOptions` (which refuses unsupported router CLI flags) and then `parseLlamaServingPreset` (which refuses unsupported preset keys) return `custom artifact configuration is unsupported: …` before any section is selected. One refused key anywhere in the file, even in another section or in `[*]`, blocks export of every model. If parsing succeeds, `customArtifactPlan` lands files under `copyAliasDir(root, sectionName)/<exportId>`, keyed by the source's section name with `requiresConfiguration:true`. So even a successful copy carries no true identity to the destination.

## Mapping to owner expectations
- **E2 (true identity as tags, no context in name):** missing. The only identity is the section name; repo, quant and file are never published. HF IDs are de-quantized by the formatter.
- **E3 (profiles copyable between nodes with the same model):** needs node-independent content identity, which exists only in envelope mode.
- **E8 (Models tab grouped by model+quant, which nodes hold it, send with progress):** grouping key missing. Send works for HF-cache and receipts but fails for MSI's preset.
- **E11 (validate bound to exact model file):** needs a stable content identity. Today there are only sample bindings (`ArtifactBinding`) or envelope digests.
- **E5 / routing (T-B):** with no digest there are no measurements, so llama.cpp nodes cannot be compared.

## What a fix would have to touch
1. **Tolerant artifact-resolution parse** (small; engine-manager `modelcopy_export.go`, `serving_llamacpp.go`). Add a non-envelope preset reader mode used by `resolveLlamaArtifactsSelection` when `rt.Serving == nil && len(rt.ModelLoads)==0`. It should accept any key and extract only `model`, `model-draft`, `ctx-size` and `parallel`, applying the same precedence as `[*]`, then section, then CLI and env. Reuse `llamaPresetOptionKey` and `llamaConsumedPaths`. This fixes export and inspection on MSI.
2. **Per-model identity metadata in inventory** (medium; engine-manager `models.go` `ModelsResult` plus `modelsSweep`, desktop `model-download.ts` `parseModelsResult` and `ModelItem`). Add an optional `modelInfo[engine][model]` with `{repo, revision, files[{name,size,sha256?}], quant, configuredContext, slots, architecture, generalName, contentId?}`, filled by reusing `resolveLlamaArtifacts`: the HF-cache branch gives repo, tag and LFS sha256; the preset branch gives the model path and maps `models--o--r/snapshots/<c>/` back to repo and commit. Cache it per source binding (`exportBinding`) so the sweep does no new I/O on unchanged files. The proxy `/v1/models` can stay name-keyed.
3. **gguffacts allowlist** (small; `shared/gguffacts/reader.go`). Retain `general.name`, `basename`, `size_label`, `file_type`, `quantized_by` and `repo_url` as bounded strings or numerics, for a quant fallback when the file is not in an HF layout.
4. **Content identity** (medium; engine-manager `modelfiles.go` and `serving_identity.go`). Compute `contentId` with the `servingContentDigest` formula from LFS sha256 or a persisted one-time `hashCache` result (persist keyed by path+size+mtime+sample). Publish it as non-strict metadata, not in `ModelDigests`, unless the owner chooses to give it strict meaning. Use it for desktop grouping, copy "already present" and the planned name-based measurement identity (which could then become content-based).
5. **Desktop display** (small to medium; `format-model-display-name.ts`, `ModelManager.tsx`, `node-configuration.store.ts` `roleLabel`, `NodeDeclaredRoles.tsx`). Show `repo` and `quant` tags from `modelInfo`, keep the section name as a secondary "profile/alias", and stop dropping `:QUANT`.
6. **Cluster sameness for routing and copy** (large; overlaps the roles/profiles units). Tiers and roles keyed by `contentId` (or repo+quant) rather than per-node names. This needs the proxy/broker to map the cluster identity to per-node served names. Reuse `nodepolicy` roles and the proxy tier search; do not add a second registry.

## Open questions / not verified here
- What llama.cpp's router `/models` actually returns in preset mode (`path`, `status.args`, `in_cache`?). If it includes the model path, metadata could come from the native list without file I/O. Unverifiable here.
- Whether MSI's launch text includes the fixed `--ctx-size 8192` (C19), and whether Windows HF caches use symlinks into `blobs/` or copies. If they are copies, the LFS sha256 is unavailable and a full hash is needed.
- Whether the owner wants a content identity to carry strict-admission meaning (writing `ModelDigests`) or to stay display/measurement-only.
