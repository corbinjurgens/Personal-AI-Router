# L5 — Desktop information architecture inventory: navigation, node settings surfaces, model surfaces, reusable pieces

Baseline: integration/join33 4eccd05d. Investigated: 2026-10-31.
Paths below are relative to `desktop/src/` unless shown absolute.

## Verdict

The renderer has one overview window with two top-level tabs, "Overview" and "Settings". Settings has three sub-tabs: "Cluster", "Routing & resources" and "Service". Per-node editing exists in two places: inline on each Overview node card (engine switch, engines, per-engine settings, models), and in "Routing & resources" behind a node picker (roles, engine bindings, node policy JSON, model settings, bulk roles). Both reach the same node-scoped stores and the same `window.pairApi` calls. There is no toolbar Halt control: the toolbar (`ContentBar`) has only "Endpoints" and "Add node", and the existing immediate stop is the per-node "Stop local models now" button. Model inventory is already cluster-wide in the renderer (`engine-models.store` is keyed `nodeId:engineType` for every node), but the only model UI (`ModelManager`) is rendered per node per engine inside a node card or the Models accordion. The model label formatter drops the quantization for llama.cpp names. Roles are stored and displayed as raw `model (engine)` pairs with no profile layer. The policy `profiles` array holds only per (engine, model) request-option preferences, not launch configuration.

## Findings

### 1. Navigation map

**Window and shell.** `ui/components/App.tsx` `App` renders `TrayApp` (lazy) when `isTrayWindow`, else `MainApp/MainApp.tsx` `MainApp`. `MainApp` renders `AppBar` (title "NVIDIA PAIR" from `shared/constants/app.ts` `APP_DISPLAY_NAME`; window controls only), `ErrorModal`, the body, `EndPointModal`, `AddNodeModal`, `InviteApprovalModal`, `WelcomeModal` (first run), `AppMessageModal`, and `InferenceDemoToast`. The body is `ServiceStoppedNotice` or a loader ("Fetching nodes", "Starting service...") while blocking, otherwise `MainApp/Content.tsx` `ClusterContent`.

**Top-level tabs** (`MainApp/ContentBar.tsx` `ContentBar`, `TAB_ITEMS`):
- "Overview": `WorkloadListView` + `WorkloadNodeConnections` + `NodeList` (`NodeList/NodeList.tsx` `NodeList`: online nodes as `NodeCardDetails`, then offline nodes as `NodeList/OfflineNode.tsx` `OfflineNode`).
- "Settings": `Settings.tsx` `Settings`.

Toolbar buttons next to the tabs: "Endpoints" (`MainApp/EndPointModal.tsx` → `EndpointContent.tsx`) and "Add node" (`AddNodeModal.tsx`). There are no other toolbar actions.

**Settings sub-tabs** (`Settings.tsx` `SETTINGS_NAV_ITEMS`, rendered through `ResponsiveNavLayout.tsx` `ResponsiveNavLayout`, a `VerticalNav` at width ≥ 640 px, else `Tabs`):

| label (exact) | id | renders | notes |
|---|---|---|---|
| "Cluster" | `cluster` | `ClusterSettings/ClusterSettings.tsx` | IP, pairing port, leave, join requests, pending invites, connected nodes, available nodes; per node "Edit node" / "Remove from cluster" |
| "Routing & resources" | `routing` | `RoutingSettings/RoutingSettings.tsx` | node picker "Select node"; per-node editing (see §3) |
| "Service" | `service` | `ServiceSettings/ServiceSettings.tsx` | service status and Start/Stop/Restart (Electron), logs, Reset app data, Application updates, About |

**Tray** (`TrayApp/TrayApp.tsx` `TrayApp`, `TrayNodeRow.tsx` `TrayNodeRow`): title "NVIDIA PAIR"; button aria "Open tray menu" (`windowApi.window.showTrayMenu`); one row per online node (click → `windowApi.window.focusNode`); button "Open NVIDIA PAIR" (`openOverview`) in the stopped state; states "Connecting...", "No nodes available". The tray has no settings, engine or model controls.

**Welcome/first-run and invitations** live in `Welcome/WelcomeModal.tsx` and `InviteApprovalModal.tsx`; they are modal and outside the tab tree.

### 4. Model surfaces

**Per node, per engine.** `ModelManager/ModelManager.tsx` `ModelManager({backend, nodeId})` is the only model list. **Copy between nodes.** `ModelManager/ModelCopyModal.tsx` `ModelCopyModal` (625 lines) is engine-scoped (`engineType` prop). **Hub.** `ModelHub/ModelHubContent.tsx` `ModelHubContent`: `searchEngineHub(engine, query)` → `engines.searchHub(engineType, query)` (per engine, cluster-agnostic). **Per node or cluster-wide?** Inventory data is cluster-wide in the renderer (`engine-models.store`), and `RoleEditor` already filters it per node. The UI that renders models is per node and per engine. Downloads and deletes take a node id. There is no cluster-wide model list component.

**Labels.** `formatModelDisplayName` (`ui/utils/format-model-display-name.ts`): branch `lm-studio` strips an HF prefix and extracts a trailing `(Q…)` from the filename; branch `ollama` uses `formatOllamaModelName`; default (llama-cpp, unknown) uses the HF formatter, which removes the `author/` segment and `-GGUF[:quant]`.
