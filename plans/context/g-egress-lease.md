# Execution plan: G — public egress lease (hybrid-routing P4.1)

## Goal

Land the broker-issued five-second public-egress lease and the proxy permission/reservation/pre-send boundary, with deterministic failure and race coverage. G lands disabled: no production request can disclose content to a public provider. A persisted revocation whose activation fails remains pending/error and stops new public attempts no later than five seconds after the last eligible renewal. Local/concrete routing and already-dispatched accounting retain their existing behavior. P4.3 package I receives one stable single-attempt entry point; real provider activation remains a separate gated change.

## Change scope

Intent: implement P4.1's lease and public-attempt gate at the existing broker policy, proxy admission, D ledger and E adapter owners.
Scope: Bounded improvement — add the lease mechanism and connect E's final send boundary; preserve the existing process model and local routing.
Basis: roadmap G, hybrid-dispatch Task 1, and the owner's binding 2026-10-20 disabled-landing decision.
Compatibility: preserve policy schema, persisted/active revision envelopes, D's durable ledger format and liabilities, E's supported protocol, PG authorization and SR resident-operation fences. Add private broker-to-proxy wire methods only.
Non-goals: unified routing/selection/cancellation, live provider qualification, provider activation, new configuration controls, ledger recovery/refund operations, UI, engine operations and performance claims.

- Use a five-second monotonic lease, renewed once per second only for an exactly matching persisted desired revision and acknowledged active proxy incarnation. Startup, activation uncertainty, failed activation, stale acknowledgements and expired grants fail closed; transient renewal RPC errors are re-evaluated next tick. `ErrReplaced` alone does not disqualify the adopted, exactly acknowledged document. Permission revocation blocks the next attempt; work already accepted for dispatch can complete and retains accounting.

## Decisions made while writing this plan

- Use receiver-clock deadlines, not a TTL restarted on receipt. Every renewal acknowledgement carries proxy monotonic `nowNanos`; a renewal with `notAfterNanos: "0"` is anchor-only. Calculate grants in the proxy's clock domain using a conservative broker anchor to prevent delayed in-order renewals from extending the five-second bound. The anchor lasts for the proxy run; re-anchor only on run change or rejected binding.
- Keep one lease state per proxy and one renewal job per broker Serve lifetime. Lease state contains run/revision binding, monotonic deadline, sequence high-water and activation-transition state; it is not durable policy or a second policy authority.
- Drop the previously proposed durability-confirmed tracker. `ErrReplaced` leaves complete new bytes at the target; existing `persistPolicy` adopts and pushes them, so renewal of that exactly active document grants nothing beyond the persisted policy. Preserve the save error and test continued renewal after matching activation.
- Make `(*Proxy).runPublicChatAttempt` the sole future production wrapper around E. Keep E's low-level injected runner usable for synthetic library tests, and put the final guard immediately before `http.Client.Do`. I consumes the wrapper instead of creating another permission/reserve path.
- Define dispatch acceptance at the final guarded HTTP handoff, matching the existing accepted-work contract. No blocking operation is permitted between successful acceptance and `Do`. Tests poised before acceptance must lose to revocation; a stream accepted before revocation is in flight, not a new attempt. This does not claim that software mutexes make a socket write physically atomic.
- Keep trial accounts distinct from qualified permanent-free accounts. G enforces the mandatory `PaidAllowed` check for `BillingPaid`; I retains classification/order/free-only eligibility ownership and cannot treat a trial account as a permanently free candidate. G adds no new trial-credit spending policy.
- Use a serial task chain because proxy/broker integration and the final source/contract join depend on the preceding interfaces. No implementation fork remains open; added-file reservation and machine access are execution prerequisites, not alternate designs.
- Fork-scan adjudication: disjunctions below enumerate prohibited inputs, failure conditions and existing evidence categories. The Mac fallback has an objective isolation prerequisite; PC3's installed-service procedure is conditional on documented fixture isolation. These are execution conditions, not unresolved design choices. No behavior/security question needs the owner before this plan can be used.
