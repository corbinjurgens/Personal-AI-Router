# Execution plan: I — unified dispatch, identity and cancellation (P4.3)

## Goal

Use one request owner and one attempt implementation for concrete, hybrid local, paired-peer and public Chat dispatch. Permission, durable reservation, final send acceptance, raw first-body commitment, delivery and accounting must have distinct, testable boundaries. Bound proxy-owned buffering process-wide, reject stale process/request cancellation, and preserve destination-local Off/pause. Land disabled for public egress. Supply SC-b with a request-owned response sink without claiming that transparent continuation exists yet.

## Change scope

Intent: replace competing inference lifecycle authorities at their existing owners and complete P4.3.
Scope: Structural change — establish the shared request/attempt lifecycle across the existing proxy and its real identity/cancellation consumers. Keep scheduling, ledger persistence, qualification and capacity authority in their current subsystems.
Basis: the owner's package-I request and roadmap outcome explicitly require a reusable dispatch foundation; a second hybrid retry loop around the existing concrete loop cannot satisfy it.
Compatibility: preserve ordered `resolveTierCandidates` output, concrete route/dialect behavior, D's durable ledger format and liabilities, G's lease authority, SR uncertain-capacity rules, SC framing and T2 destination-only observations. Require complete incarnation-qualified cancellation; older displayed workloads lacking a run remain displayable but cannot be cancelled. Public provider activation stays unavailable.
Non-goals: SC-b continuation execution/prefix reconstruction, J0 history/projections, J1/J2 diagnostics, new engines, Ollama operation, provider qualification/activation, ledger recovery/refunds, a scheduler rewrite, engine starts and RSS guarantees.

## Decisions (settled — do not revisit)

- PerRequestCeiling is cumulative over one logical routing request, across retries, fallback, local, peer and public attempts. An attempt reserves only remaining allowance. Local/peer attempts currently have no public monetary hold; they still share the same request owner, deadline, exclusions and ceiling state. Zero nano-USD means zero spend, not unlimited.
- Owner Q1 answer (2026-10-20, binding): use the tightest (lowest) PerRequestCeiling of any paid account tried so far in this request. Before trying a paid account, monotonically tighten the ceiling using its current validated policy value; never increase it within the request. Grant a new reservation only when the cumulative sum of all granted reservation upper bounds including the proposal fits that ceiling. If tightening puts prior grants above the new ceiling, refuse this and further paid reservations; do not undo prior grants. Settlement never replenishes allowance. Free/local/peer attempts neither pin a zero monetary ceiling nor reset the accumulated state. Daily/monthly account checks remain independent.
- Owner Q2 answer (2026-10-20, binding): configure the process aggregate owned-buffer cap in MiB, default 256, and acquisition wait in seconds, default 5. Wait 0 disables waiting. Aggregate exhaustion waits for room up to the configured deadline; expiry/immediate refusal is HTTP 503 busy. Individual request overflow remains immediate HTTP 413 and never waits. These are owned-buffer limits, not RSS guarantees.
- Destination-local Off/pause wins at admission and immediately before dispatch, including SR wake and NE paths. A peer hint never substitutes for that veto.
- G alone grants public permission and owns the public-attempt wrapper; D alone reserves/settles liabilities; admission alone owns destination capacity. I owns lifecycle, response and typed cleanup. Public routing stays disabled in this package.
- The user sees a delay/pause followed by same-model continuation whenever qualified continuation is possible; surface an error only after that possibility is exhausted. I supplies the sink boundary, not SC-b's executor. At I's endpoint no qualified continuation implementation exists, so interruption is classified as continuation-unavailable and produces SC-a's clean terminal error. Do not label this transparent resume delivered. SC-b later replaces that disposition before sink termination.
- Continuation eligibility remains same immutable content digest, engine family, current prefill qualification and context fit. Public continuation is unavailable. No cross-model splicing, prefix persistence or heuristic recovery.
- Each pre-commit hybrid local attempt has an ordinary local workload, ended before a public fallback. Public attempts create no cluster workload. I must not resurrect terminal jobs.
- Keep concrete regenerate compatibility: pre-commit regenerate excludes the current node and retries; after commit it cancels the request. Hybrid `workloads:cancel` cancels only the request still linked to that live local workload and never triggers public fallback. Hybrid pre-commit regeneration uses origin-local `routing:cancel`; post-commit regenerate is a conflict with no cancellation side effect.
- Do not start Ollama. Product integration for this work is OpenCode over Chat Completions. Preserve existing dialect fixtures and compatibility without executing installed engines.

## Decisions made while writing this plan

- Use a request mutex to arbitrate one immutable active attempt and its transition/reason. Capture attempt identity in every timer, ticket, transport callback and accounting callback. Delete the old `attemptClaim`/`redispatch` competing authority at cutover; keep one common driver with concrete/hybrid policy inputs.
- Separate accepted handoff, raw successful first-body commitment, downstream exposure, protocol completion, successful delivery and accounting disposition. A parse error after the first raw byte cannot authorize fallback. A settlement error after completed delivery cannot rewrite success into a resend.
- Restart safety means stale-key rejection and no automatic resumption/replay after replacement, not exactly-once engine execution or billing. Retain D's uncertain holds. Do not add a durable routing journal.
- Carry origin binding through the existing private `node/set-policy` request/ack exchange: change that IPC payload to `{originNodeId, policy}` using a shared `SetPolicyParams` envelope, leaving persisted Policy unchanged. Ack becomes `{originNodeId, revision, runId}`. Pin origin to the exact proxy run and reject mutation within a run. Broker validates origin/run/revision on the exact process handle; no client-supplied identity can establish it. Install the binding before opening dispatch. Update every producer/fixture atomically; accept no old naked-policy IPC fallback. This avoids a parallel identity service and preserves G's revision/run lease binding.
- Use a fresh 128-bit cryptographic proxy-run nonce: widen `newRunID` to 16 bytes and delete its timestamp branch. Go 1.25 `crypto/rand.Read` fills the buffer or crashes; do not add a constructor error path. Process-wide request counters do not reset per facade; checked exhaustion refuses the next request. Namespace hybrid local workload IDs away from concrete facade counters, preserving the existing workload wire ID type.
- One process byte allocator owns inference buffering, with bounded context-cancellable FIFO waits. Retain the 64 MiB individual request cap and SC's 1 MiB frame/64 MiB category limits; no disk spill or second SC global pool. Use integer `routing.buffers.capacityMiB` in [192, 1024] and `routing.buffers.waitSeconds` in [0, 600], defaults 256 and 5. The owner-approved minimum (2026-10-21) is 192 MiB; it exceeds the 129 MiB arithmetic floor of two maximal 64 MiB allocations plus a separately charged one-byte overflow probe. Task 4a clamps body growth to the effective individual limit. At activation also require capacity bytes >= `2 * effectiveIndividualLimit + 1`, with checked arithmetic, so CLI overrides cannot create an impossible chunked-body configuration. Additional representations are charged separately. The 1024 MiB/600-second upper bounds are finite plan-time choices, not owner measurements; earlier cancellation/deadlines win.
- Bound the allocator to 1024 queued acquisition records, one per synchronous acquisition call; queue overflow refuses immediately with busy. This fixed metadata bound prevents the requested wait mechanism from introducing unlimited retained waiter state. No per-wait helper goroutine. Strict FIFO permits head-of-line blocking: later small acquisitions cannot bypass a live earlier large waiter.
- Keep one file and existing referenced task numbers. Use fresh MSI sol sessions for 3a identity/fencing, 3b existing cancellation, 4a buffer wiring and 4b atomic owner/sink cutover. References to Task 3 mean 3a/3b; Task 4 means 4a/4b. Task 4b never leaves two lifecycle owners active. Task 6 remains the exclusive shared-document/new-method-registration join.
- Use one registry bounded to 1024 live entries, with a workload secondary index reused across Tasks 3/4/6. Registry and bounded cancellation snapshots are control metadata and never acquire the inference byte root. Refuse excess registrations with 503 before inference effects. Task 3a installs key/registration lifetime for the existing driver; 3b uses the workload index; 4b replaces entry payloads with sole owners; 6 exposes those entries without another map.
- Publish a minimal origin-local `routing:active` key snapshot beside `routing:cancel`, backed directly by live owners, so an API-only request can be cancelled before output. Register an owner before exposing its key and remove it on terminal cleanup. Include no content, model/provider/account data or retained history; J0 remains the history/projection owner.
- Confirm SC's proposed ownership amendment at the design level: the committed local attempt's workload is the future continuation's public workload; children have private attempt IDs. I reserves this link without new continuation children, running-with-no-placement transitions or changed destination-loss sweeps. SC-b must validate its public workload behavior before implementing those transitions; this plan does not silently change today's workload store semantics.

### Task 1 — reusable owned-byte leases with deterministic saturation

**Files:** `services/nvpair-proxy/bufferbudget.go`, `services/nvpair-proxy/bufferbudget_test.go` (new).

On insufficient aggregate room, wait at most the injected duration and the caller's earlier context deadline; wait 0 immediately refuses. FIFO order is the order of enqueue under the allocator lock: only the live head can receive a grant, and a newcomer cannot take free bytes while any earlier waiter exists. Keep a buffer charged until its final borrower exits; cancellation alone cannot release it. Subordinate categories cannot evade the root. Remove/refuse queued acquisitions now larger than the cap immediately. Capacity increases reconsider FIFO heads.
