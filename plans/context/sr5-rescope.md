# Execution plan: SR Tasks 5/6 daily-engine amendment

## Goal

Complete served/resident configuration for daily llama.cpp models: each model is served on demand unless explicitly desired resident; residency uses finite, current, model-specific qualified bounds before any load side effect. Land the finite context bound now without delaying on-demand first use for automatic residency. Publish desired versus observed state honestly through local and paired policy readback. Serving hosts are MSI and PC3; the Mac is an origin/client only. Strata and the strong tier are deferred beyond this roadmap by the owner's 2026-10-21 decision in project-home `decided.md`; no Strata adapter, fixture, documentation or live work is an SR gate. This is an executable amendment, not implementation evidence.

## Change scope

Intent: finish SR 5/6 for the actual daily engines and close the unbounded resident-context path.
Scope: **Bounded improvement** at shared nodepolicy validation, destination admission, engine-manager resident adapters, broker reconciliation, existing policy transport, and their consumers/tests/docs. Basis: the owner's 2026-10-20 milestone and explicit design brief. Earlier landed SR enforcement, B2 identity, E3 switching and PG2 permission ownership remain authoritative.

Leave Prepare/Dispatch DTOs unchanged; `ReconcileResidentParams.Load` already exists. Old target nodes remain unsupported for SR edits when readback loses served/resident fields. No new public RPC or peer resident-load endpoint.
Non-goals: model acquisition, native engine source edits, NE launch compilation/identity production, B request-shape expansion, hardware fitting/measurement, new UI controls, G/I activation, a new store/queue/scheduler, and cleanup of unrelated engine implementations.

## Decisions made while writing this plan

- Keep `PrepareResidentParams` and `DispatchResidentParams` unchanged. The proxy derives/captures context from `ProfileFor` at prepare and revalidates under its mutex at dispatch. Existing revision, strict generation and full identity invalidation revoke stale undispatched holds; manager validates the existing reconcile load against the native envelope. Broker always derives that load from the same revision's profile.
- Put the reusable context comparison in shared nodepolicy: `ValidateResidentContext(contextLength, qualifiedContextTokens int) error`, rejecting nonpositive bounds and requested context above the finite per-model bound without overflow-prone arithmetic. Use it in policy/profile-aware load validation, proxy preparation/final grant, and manager pre-load checks. A positive integer, `1<<24`, configured memory, and a qualification ID alone are never evidence of the bound. Policy-only structural validation cannot consult a live registry: an offline oversized declaration can be saved, but must remain blocked/unqualified until the runtime comparison succeeds.
- For model-only load endpoints, require requested/profile context to equal NE's native per-slot context, with B qualification covering that actual allocation and concurrency. A smaller requested number cannot shrink an already configured native allocation. Leave `ResidentLoadOptions.KeepAliveSeconds`, its validation, comments and tests untouched; non-Ollama adapters ignore it. Resident support requires idle sleep disabled in the applied preset and `RouterCapacity` (`models-max`) at least the resident count on that engine, for the preference's lifetime. Obtain the disabled spelling from NE's pinned-build contract rather than guessing zero/-1. No timer releases protection, and reconciliation never mutates native settings. Unsupported resident configuration leaves on-demand serving possible.
- Use the existing resident list for per-model mode: served but not resident is on demand. Do not add another mode enum or assume all daily models must fit resident simultaneously. The approved host record fixes the selection and combined budget; absent approval, automatic residency stays blocked.
- Keep all broker implementation and unit tests in one Task 5c reservation. Adapter work and broker work can proceed in parallel after 5a-ii and the external file releases. PG registry verification 5d is landed. Contract generation is serialized at each join.
- Coordinator-adopted defaults, owner may veto: **Q1** PC3 LFM2.5-24B-A2B resident; MSI LFM2.5 resident and Tiel-Coder-35B on demand until approved NE memory bounds show both fit. **Q2** on-demand first: land 5a-i now, 5b/5c after NE T4; do not block first use on automatic residency. **Q3 — OWNER-CONFIRM before live use:** use the owner's current llama-server preset values, `parallel=1`, idle sleep disabled for residents, `models-max` equal to resident count, and exact artifact IDs from the frozen NE host record. No numeric context/output/memory values are invented here. **Q4** yes, SR drops all Strata work; the generic manifest contract covers its future return. Defaults authorize fixtures and planning, not live allocation or engine starts.
- Recovery is deliberately bounded: a returned reconcile result establishes manager operation completion; after that barrier a fresh source-bound read can produce observe-resident recovery. A transport timeout/EOF with no completion proof stays unknown and held. Do not replay reconcile after its retention deadline to manufacture a barrier, and do not add a new operation journal/query API.
