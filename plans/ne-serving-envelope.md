# NE — non-Ollama serving envelope and identity

## Goal

Give PAIR-served llama.cpp models an authoritative, finite launch envelope and a usable content/config identity. Engine-manager owns validation, launch preparation, identity production and effective readback; E settings owns revisioned configuration and apply receipts. B can qualify the exact content/runtime/envelope, and SR can consume the validated envelope before loading. Preserve landed prepared-Strata support and its shared-code tests; further Strata work is owner-deferred on 2026-10-21. Complete the remaining NE work without implementing SR 5 reconciliation, T2, model acquisition, a new service, or a general engine-extension system.

## Change scope

**Bounded improvement.** Improve the existing engine-manager/E settings boundary and its identity consumers, including a strict-readiness envelope guard. Reuse llama.cpp's router preset and the landed generic prepared-launch path; keep opaque placement options. Extend existing contracts rather than creating another configuration database, launch supervisor, permission route, or qualification registry. Plain direct-model output enforcement is deferred Part D after I 4b, not a daily-use prerequisite.

Compatibility: existing Ollama behavior and unconfigured engine launch settings remain valid. A non-Ollama model without an NE record stays unqualified. Strict/resident paths require current identity; manager loads for an NE-configured engine remain declaration-gated. Plain direct-model forwarding retains current behavior until Part D: its output can exceed the declaration's output default within native per-slot context, and router-cached undeclared models remain reachable there. An unrelated settings edit preserves NE configuration. Existing qualified non-NE Ollama identities retain their digest semantics. No migration blesses existing processes, files, settings, or B records.

Non-goals: SR 5/6 reconciliation, resident grants/persistence/restart adapters; T2 extraction/publication; OpenCode request-shape expansion in B; ME1 measurement producers and ME2 accounting; automatic fitting/offload selection; remote wake/switch policy; a model download/import/copy feature; UI beyond preserving and exposing readback. A recorded memory bound is an operator-approved conservative admission declaration, not an OS-enforced RSS/VRAM limit or measured usage.

## Decisions

- Engine-manager is the sole compiler/validator of the NE launch record. E settings preview/apply/readback carries it through the existing revision/receipt path. Clients neither parse native presets nor calculate digests or safety bounds.
- The llama router preset is the authoritative source of native context, slots and placement. The prepared Strata config/native arguments are the corresponding source for Strata. E's NE record adds PAIR's output cap, declared memory bounds and attestations; it does not duplicate editable context/slot values. Preview derives these values from the native source and returns their source/config digest for apply-time comparison.
- Preserve landed CLI precedence: NE moves PAIR's implicit 8192/1 defaults into presets, retains supported explicit user CLI/environment values using native precedence, and rejects ambiguous/unsupported forms. Preview shows effective values. Unconfigured legacy launch keeps its defaults and remains unqualified.
- Context means usable tokens per request/slot, including prompt and generation, not router aggregate KV capacity. Record native total context separately. Validate finite positive context/slots, positive output strictly below per-slot context, checked arithmetic, and explicit finite memory bounds before spawn. Reject auto/zero/unlimited context and slots. Placement flags remain opaque strings in the launch record; do not derive a safe memory bound from them.
- Bind the exact approved envelope into launch identity. A change to model content, preset/config, tokenizer/template, draft model, learned profile, native executable/dependencies, relevant Python source, placement, retention or model-router capacity invalidates the prior qualification. A build/version label alone is insufficient.
- Preserve HF snapshot symlinks and original model locations. Only small launch configuration snapshots are materialized in PAIR's existing application data directory. No model copy, import, download, cache migration or hardlink operation is part of NE.
- Coordinator-adopted owner defaults (owner may veto): **Q1** do not cap plain direct-model requests before daily use; defer Part D until after I 4b. **Q2** use HF LFS SHA-256 values where present, otherwise a one-time external `shasum`; PAIR adds no hashing. **Q3** remove Strata from remaining NE Tasks 4–5 and the MSI gate, per owner deferral 2026-10-21. Landed Task 3 remains intact.

## Decisions made while writing this plan

These are design choices made here, not previously approved hardware settings. The owner can change them before execution.

### Identity: trusted content SHA-256 with a cheap local binding

Use trusted full-file SHA-256 values for every consumed model artifact. Prefer pinned HF LFS values; otherwise use a one-time external `shasum` operation. Preserve the landed provenance kinds (`hf-lfs-sha256`, `strata-source-verification`, `verified-manifest`, `one-time-sha256`, `supplied-sha256`); add no provenance-acceptance field to B. PAIR never invents content digests from metadata or a SHA-shaped blob name and adds no hashing feature. No full GGUF scan occurs during launch, preview, inventory polling, qualification joining or admission.

At attestation, bind each asserted digest to logical role, source path, resolved regular-file target, size, nanosecond mtime and a bounded sample SHA-256 over the first and last 64 KiB (hash the file once when shorter than 128 KiB). Retain both symlink source and resolved target. Recheck this binding before launch and during the existing inventory refresh, sampling those bounded regions even when stat values are unchanged. A changed target/stat/sample invalidates the attestation; stop publishing that model's identity until the operator explicitly re-attests. Never auto-rebind an assertion to changed bytes. Read/stat before and after sampling and reject an unstable file.

Produce `ModelDigests[modelID]` as SHA-256 of a versioned canonical manifest of each declared artifact's `Role`, `Binding.SizeBytes` and `SHA256`, preserving declared native shard order. Include every consumed artifact. Exclude paths, mtimes, samples and operator labels. Publish the same digest as `ServingEnvelope.ContentDigest`. Relocation with renewed binding preserves content identity while local launch/config identity changes. Document that this is an aggregate manifest digest. Conflicting normalized aliases produce no qualified identity.

Reuse the landed compiler's small-dependency hashes and `prepared.Digest`; no new runtime-closure work is scheduled. Define versioned NE `LaunchDigest` as SHA-256 over the existing `launchDigest` of the pre-snapshot launch plus `prepared.Digest`. Capture the original command before `preparedSnapshotCommand` rewrites argv/environment. Generation-directory names never enter this digest; non-NE hashing stays unchanged. Changed executable identity, source, declaration, placement, retention or capacity changes it.

**Why:** B already joins exact content and launch digests. A path/stat/sample fingerprint is not full content identity; bounded binding checks cannot detect a deliberate middle-only replacement preserving size, mtime and samples. Document that trust limit. Existing B records fail on a different aggregate content digest without a new provenance field. Keep ordinary Ollama inventory-digest provenance intact.

### Configuration and readback contract

Host RAM must be positive; VRAM must be an explicit nonnegative integer, with zero meaning deliberately CPU-only. Missing memory is unknown, never zero. Record placement flags, retention and router capacity from their native sources in the derived envelope. Do not add a separate persistent NE journal.

Ordinary port/text edits preserve it.
