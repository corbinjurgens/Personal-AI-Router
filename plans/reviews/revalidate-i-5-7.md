## Findings

### RED-1 (carried from debate-i-g RED-1; still open at 7c9bfb5 and still unowned): departed-run local-origin workloads are never retired, and Task 7's restart case has nothing to assert against

- Claimed invariant (common brief, daily milestone): "honest completed/failed/cancelled outcomes including interrupted streams" and "headless service with Windows service-process restart". I Task 7 Do: "Cover broker/proxy restart ... late old notifications/cancels".
- Code path (VERIFIED at 7c9bfb5): when a new proxy incarnation binds, the broker resets `incarnation, runID, activeRevision, activationErr` (`B/policy.go:1282`) and replays policy; nothing walks the workload store. The only inferred-terminal producers remain `failWorkloadsForNode` (discovery departure, `B/workload_projection.go:652`) and `failStaleForeignWorkloads` (remote-origin records only, `:740`). Active records are never restored across a broker restart (`B/workloadstore/persistence.go:17-19`), so the hole is the proxy-only crash/respawn that the supervisor exists to handle (`B/supervisor.go:235-293`). The replacement proxy's `workloadCancelControl` requires `target.RunID == p.runID` (`P/request_registry.go:119`), so the old run's records answer `found=false` forever. 4b changed none of this (groundwork's only `workload_projection.go` change since the 4b base is the node-reference projection bound).
- Observed result: INFERRED from code, not executed (would need a process fixture, which is Task 7's own territory).
- Affected state: broker workload store local-origin active records, scheduler pending counts, workload-manager anti-entropy set, desktop/TUI job cards.
- Disposition: amend plan. The producer is a small broker change outside every reserved I File: on incarnation replacement (`B/policy.go:1282` or `stopProxySupervisorLocked`, `B/proxy.go:458-470`), retire every open local-origin record whose `RunID` differs from the new run with the inferred-terminal provenance `failWorkloadsForNode` already uses. It needs a coordinator Files reservation (`B/workload_projection.go`, `B/policy.go` or `B/proxy.go`, their tests) and sits in the SR 5c -> PA 1-2 broker lane. Brief I7-a below assumes it exists and names the dependency explicitly; without it the restart case can only prove "the replacement's run cancels nothing of the old run", not retirement.

### UNVERIFIED-1: a committed stream that ends through the sink's synthetic error can be recorded as a completed performance sample (the repair the handoff calls "in progress")

- Claimed invariant (common brief, milestone): "accurate-or-unknown telemetry". I Task 4b Do: "Record accounting failure independently from stream/protocol failure"; "Nonstream completion still requires accepted response, clean EOF and successful delivery".
- Code path (VERIFIED reads, INFERRED consequence): when `awaitFirstBody` fails after commitment, `ModifyResponse` substitutes `interruptedBodyForAttempt(..., att)` and clears `err` (`P/routing.go:1361-1398`, `:1429-1433`), so `installResponseStream` is never called and `performance.reader` stays nil. The attempt's `originResponseBody` wraps the synthetic body (`:1451`), whose `Read` reaches `io.EOF` and sets `complete = true` (`P/http_handler.go:526-529`). `performanceAttempt.finish` then takes the `reader == nil` branch: `returned && sc.upstreamBody.complete && sc.wroteErr == nil && parent.Err() == nil && 2xx` and `sink.result().DeliveryComplete` (`P/performance.go:836-839`). `DeliveryComplete` is true for a delivered synthetic ending: `streamFinished` is set by `responseInterruptionBody.Read` at EOF (`P/response_sink.go:248-252`, `:154`), `written == produced` holds because `output(n,false)` precedes each write (`:255`), and nothing in that branch checks `ProtocolComplete` (false) or `ContinuationUnavailable`/`Reason`. The measurement is therefore `OutcomeCompleted` for a stream the client saw end with `stream_interrupted`. The workload event is correct (`proxyErr = ctl.sink.result().Reason` at `P/routing.go:1471`, then `emitTerminal("failed", ...)` at `:839-844`); only the performance record is wrong.
- Probe not run: proving it needs a fixture that times out after the first byte and inspects the enqueued `performancewire.Sample`; `TestUnifiedDispatchCommittedPeekTimer` asserts the workload/sink side only (`P/routing_test.go:1366-1552`, greps for `Outcome`/`performance` inside it find nothing).
- Affected state: `performancestore` samples (`OutcomeCompleted` with nil `ProtocolComplete` and no numeric fields), hence T2 projections.
- Disposition: repair now, inside 4b before merge (it is the handoff's "repair in progress"); the branch at `7c9bfb5` does not yet contain it. Tasks 5-7 depend on it only in that I7-a's process evidence must not assert telemetry before it lands. Suggested shape: in the `reader == nil` branch require `sink.result().Reason == ""` (or check `!ContinuationUnavailable`) before `OutcomeCompleted`, and treat a non-empty reason as `OutcomeFailed` with `ProtocolComplete = &false`.
